# Scroll Race production-readiness campaign

Status: **clean local pass** on 2026-07-23.

This campaign uses only deterministic synthetic names, scores, devices, and
countries. It does not connect to the production site, production Netlify
Blobs, real user data, or secrets.

## Production-like test boundary

- Runtime: a fresh `vite build` followed by `vite preview` bound to
  `127.0.0.1:20073`.
- Browser: Chromium through the checked-in Playwright dependency.
- World board: the real browser client and validation/normalization code with a
  deterministic route double. The Netlify function itself is integration-tested
  against an in-memory Blobs implementation.
- Storage: real browser `localStorage` and `sessionStorage`.
- Viewports: 320x700, 390x844, 1280x800, and 1440x900.
- Motion: normal and `prefers-reduced-motion: reduce`.
- Network: live-scale response, empty board, HTTP 503 fallback, and hostile
  response shapes.

## Synthetic scale

`npm run data:generate` creates `.readiness-runtime/production-scale.json`.
The generated file is ignored because it is reproducible from
`.smoke/production-data.mjs`.

| Dimension                       |                    Scale |
| ------------------------------- | -----------------------: |
| Events                          |                        4 |
| Stored world entries per event  | 100 (the production cap) |
| Served world entries per event  |   25 (the API page size) |
| Rendered world entries          |                       10 |
| Local entries per event         |       10 (the local cap) |
| Simulated lifetime world totals |       125,000 to 537,593 |
| Real names or identifiers       |                        0 |

## Reproduce the clean pass

```powershell
npm install
npm run data:generate
npm run test
npm run lint
npm run check
npm run audit:prod
npm run test:readiness:local
git diff --check
```

`test:readiness:local` owns its local preview lifecycle so a stale build cannot
silently serve old asset references. To use another port, set
`SCROLL_RACE_READINESS_PORT` before running it.

The latest browser report and screenshots are written to
`.smoke/readiness-evidence/`. The directory is intentionally ignored because
every artifact is regenerated by the command above.
